# Apple Screen Time API (FamilyControls / ManagedSettings) — Falsifiable Claims with Evidence (as of mid-2026)

## 1. FamilyActivityPicker and token opacity

- **Claim: `FamilyActivityPicker` is a SwiftUI-only `View` (struct conforming to `View`, `@MainActor`), available iOS 15+, with `init(selection:)` and `init(headerText:footerText:selection:)`, plus a `familyActivityPicker(isPresented:selection:)` modifier for sheet presentation. There is no UIKit equivalent; UIKit apps must wrap it in `UIHostingController`.**
  - Source: [Apple doc — FamilyActivityPicker](https://developer.apple.com/documentation/familycontrols/familyactivitypicker) (abstract: "A view in which users specify applications, web domains, and categories without revealing their choices to the app").
  - Confidence: Apple official doc. (The "wrap in UIHostingController" part is standard SwiftUI practice, not a doc quote.)

- **Claim: The picker returns a `FamilyActivitySelection` with `applicationTokens: Set<ApplicationToken>`, `categoryTokens: Set<ActivityCategoryToken>`, `webDomainTokens: Set<WebDomainToken>`, plus `applications`/`categories`/`webDomains` sets and an `includeEntireCategory: Bool`. It conforms to `Codable` and `Equatable`.**
  - Source: [Apple doc — FamilyActivitySelection](https://developer.apple.com/documentation/familycontrols/familyactivityselection).
  - Confidence: Apple official doc.

- **Claim: Tokens are deliberately opaque for privacy — "To protect the user's privacy, the system uses opaque values to represent the selections" (picker doc), and WWDC21: "Family Controls provides opaque tokens that represent apps and websites… ensure that no one outside of a single Family Sharing group will know what apps and websites are being used."**
  - Sources: [FamilyActivityPicker doc](https://developer.apple.com/documentation/familycontrols/familyactivitypicker); [WWDC21 "Meet the Screen Time API"](https://developer.apple.com/videos/play/wwdc2021/10123/).
  - Confidence: Apple official.

- **Claim: The host app CANNOT read app names or bundle IDs from tokens. `Application(token:)` yields `bundleIdentifier == nil` and `localizedDisplayName == nil` in the main app. The ONLY documented context where these are non-nil is a shield-configuration extension. Apple doc for `Application.localizedDisplayName`: "In an extension that provides shield configurations, this property provides the app's name. When you access this property outside that extension, the value is `nil`. See `ShieldConfigurationDataSource` in the Managed Settings UI framework." Identical wording for `bundleIdentifier`.**
  - Sources: [Application.localizedDisplayName doc](https://developer.apple.com/documentation/managedsettings/application/localizeddisplayname); [Application.bundleIdentifier doc](https://developer.apple.com/documentation/managedsettings/application/bundleidentifier); [forum thread 782492](https://developer.apple.com/forums/thread/782492) confirming nil in-app on iOS 17.
  - Confidence: Apple official doc + forum confirmation. Note: some reports suggest `DeviceActivityReport` extensions can also render app names (via the report UI, which runs sandboxed and can't exfiltrate data back to the app) — that mechanism displays names but still never returns strings to the host app. Flagged: the doc quote names only the shield-configuration extension.

- **Claim: To display selected apps in your own UI, pass a token to SwiftUI `Label` — `Label(applicationToken)` / `Label(activityCategoryToken)` / `Label(webDomainToken)` (FamilyControls extends `Label` with these inits; Apple has a "Displaying Activity Labels" doc page). The label shows icon/name read-only; you still can't extract the string.**
  - Sources: [Apple doc — Displaying Activity Labels](https://developer.apple.com/documentation/familycontrols/displayingactivitylabels); [forum thread 782492](https://developer.apple.com/forums/thread/782492) ("You can pass any of the tokens to the SwiftUI Label constructor to show the app name and/or icon").
  - Confidence: Apple official doc + forum. Note: multiple community reports (unverified here) say `Label(token)` sometimes renders blank inside certain extension contexts.

- **Claim: On a parent's device in Family Sharing, the picker lists apps/websites from authorized child devices; on an individually-authorized device (iOS 16+ `.individual` authorization) it lists that device's own apps. Doc: "A FamilyActivityPicker shown on a parent device only displays applications and websites from authorized child devices within the Family Sharing Group."**
  - Source: [FamilyActivityPicker doc](https://developer.apple.com/documentation/familycontrols/familyactivitypicker).
  - Confidence: Apple official doc.

## 2. Token persistence and stability

- **Claim: `FamilyActivitySelection` is Codable and is commonly persisted (JSON-encoded) in UserDefaults, typically in an App Group container so shield/monitor extensions can read it. This is the community-standard pattern; Apple does not document an official persistence mechanism.**
  - Sources: [FamilyActivitySelection doc (Codable)](https://developer.apple.com/documentation/familycontrols/familyactivityselection); pattern shown in [pedroesli blog](http://pedroesli.com/2023-11-13-screen-time-api/), [kingstinct/react-native-device-activity](https://github.com/kingstinct/react-native-device-activity).
  - Confidence: Apple doc (Codable) + multiple community sources (pattern).

- **Claim: Tokens are NOT guaranteed stable long-term. iOS has silently re-issued new tokens for the same apps, so tokens stored by the app stop matching tokens the system passes to `ShieldConfigurationDataSource`/`ShieldActionDelegate`, producing blank/generic shields. A major regression began with iOS 17.5/17.5.1 (June 2024) and per developers was still reproducing through iOS 18.x and iOS 26 betas (July–Aug 2025). Apple DTS (Quinn) on the lead thread: "As far as we can tell this is a bug. There's no code-level workaround, because tokens are opaque by definition." Lead Feedback: FB14111223 (plus FB14082790, FB15500649, FB18353106, others). The only mitigation is having users re-select apps in the picker (and it can recur days later), plus falling back to a generic shield UI for unrecognized tokens.**
  - Sources: [forum thread 758325 "Tokens change without reason after updating to iOS 17.5.1"](https://developer.apple.com/forums/thread/758325); [forum thread 732845 "ApplicationTokens changing"](https://developer.apple.com/forums/thread/732845); [riedel.wtf "Apple's Screen Time API has some major issues"](https://riedel.wtf/state-of-the-screen-time-api-2024/) (by the developer of "one sec": "iOS randomly changes tokens sometimes").
  - Confidence: Multiple independent forum reports + Apple DTS acknowledgment on-thread. Strong. Version-dependent: check whether a 2025/2026 iOS release fixed FB14111223 before relying on this.

- **Claim: Specific token-change triggers reported by developers: (a) OS updates (esp. 17.5.1), (b) joining/changes to an iCloud Family ("if you join an iCloud family… tokens will be updated at this moment" — thread 732845), (c) rare unexplained rotation. Old tokens may keep working for shielding while no longer matching new tokens delivered to extensions.**
  - Sources: [thread 732845](https://developer.apple.com/forums/thread/732845) (includes captured before/after token payloads); [thread 758325](https://developer.apple.com/forums/thread/758325).
  - Confidence: Multiple forum reports; not in official docs.

- **Claim: Tokens are device-scoped: a token generated on device A is not valid on device B (transferring an encoded FamilyActivitySelection to another device and using the token errors/nulls). Exception: in the parent/child Family Sharing flow, the parent's picker intentionally yields tokens for the child device's apps.**
  - Source: forum reports surfaced in search (device A → device B token "null" report); consistent with the opaque, per-device design in [WWDC21](https://developer.apple.com/videos/play/wwdc2021/10123/).
  - Confidence: Forum reports + design inference; no explicit Apple doc statement found. Flagged as inference.

- **Claim: Tokens generally survive ordinary device reboots and host-app relaunches (day-to-day persistence works — the entire ecosystem of shipping blocker apps depends on it), but survival across device restore/migration to a new device is NOT guaranteed and failures are reported; there is no Apple documentation promising any stability duration at all.**
  - Sources: absence of any stability guarantee in [FamilyControls docs](https://developer.apple.com/documentation/familycontrols); riedel.wtf and forum threads above for invalidation cases.
  - Confidence: Reboot-stability is community consensus (no counter-reports found); restore/migration fragility is multiple forum reports. Explicitly flagged: I found no authoritative statement either way about app-reinstall (of the host app or the target app) preserving tokens — treat stored tokens as best-effort cache, re-derivable only via a fresh picker session.

## 3. FamilyActivityPicker bugs and limits

- **Claim: The picker crashes/freezes (blank view) when expanding a category or search result with many items — reported ~50% crash rate around 100 items, ~100% at 200+. Root cause per developers: the picker UI runs out-of-process in `com.apple.FamilyControls.ActivityPickerExtension` (FamilyControlsAgent), which hits an ~50 MB extension memory limit; logs show "Connection to plugin interrupted while in use." An Apple Frameworks Engineer replied: "This is a known bug, please follow up with your bug report(s)." Known since iOS 16; feedbacks FB11400221, FB14067691, FB16756355. Workaround: detect the dead remote view (e.g., timer-driven redraw/opacity toggle in a ZStack) and show fallback UI.**
  - Sources: [forum thread 764457](https://developer.apple.com/forums/thread/764457); [thread 766506](https://developer.apple.com/forums/thread/766506); [thread 743770](https://developer.apple.com/forums/thread/743770); [thread 724556](https://developer.apple.com/forums/thread/724556); [kingstinct README](https://github.com/kingstinct/react-native-device-activity) ("prone to crashing, especially when browsing larger categories of apps or searching").
  - Confidence: Multiple forum reports + on-thread Apple engineer acknowledgment. Version-dependent (iOS 16–18 era reports; re-verify on current iOS).

- **Claim: There is NO documented Apple limit on how many apps can be selected in the picker itself. The practical "50" ceiling comes from ManagedSettings (below): shields silently fail past 50 tokens. Apps that show "maximum of 50" text in the picker are using their own `headerText`. Selections with `includeEntireCategory: true` can be very large ("The activitySelection tokens can be particularly large") and large selections aggravate memory/crash issues.**
  - Sources: [FamilyActivityPicker doc](https://developer.apple.com/documentation/familycontrols/familyactivitypicker) (no limit stated); [thread 733361](https://forums.developer.apple.com/forums/thread/733361); [kingstinct README](https://github.com/kingstinct/react-native-device-activity).
  - Confidence: Absence-of-doc claim (falsifiable by finding a doc'd picker limit) + multiple community sources for the practical behavior.

## 4. ManagedSettingsStore

- **Claim: `ManagedSettingsStore` is "A data store that applies settings to the current user or device" (iOS 15+). Setting groups: `account`, `appStore`, `application`, `cellular`, `dateAndTime`, `gameCenter`, `media`, `passcode`, `safari`, `shield`, `siri`, `webContent`. Setting a value to nil removes it: "Changing the value of a setting to `nil` deletes your app's configuration for that setting from the device." Also: "The system doesn't guarantee that the settings you specify govern the device's behavior" — the system computes effective state from all sources (multiple stores/apps: most-restrictive wins, per WWDC22: "The most restrictive setting always wins").**
  - Sources: [ManagedSettingsStore doc](https://developer.apple.com/documentation/managedsettings/managedsettingsstore); [WWDC22 110336](https://developer.apple.com/videos/play/wwdc2022/110336/).
  - Confidence: Apple official.

- **Claim: `shield.applications: Set<ApplicationToken>?`, `shield.applicationCategories: ShieldSettings.ActivityCategoryPolicy<Application>?` (cases `.none`, `.all(except:)` — "shields all apps and websites, except content that you specify", `.specific(_:except:)`), and `shield.webDomains` / `shield.webDomainCategories` are the shielding settings.**
  - Sources: [ShieldSettings doc](https://developer.apple.com/documentation/managedsettings/shieldsettings); [ActivityCategoryPolicy doc](https://developer.apple.com/documentation/managedsettings/shieldsettings/activitycategorypolicy).
  - Confidence: Apple official.

- **Claim: Named stores `ManagedSettingsStore(named:)` are iOS 16+. The 50-store limit is stated in the WWDC22 session, verbatim: "Now, in iOS 16, you can create up to 50 Managed Settings Stores per process, each with their own unique name. These named stores are also automatically shared between your app and all your app extensions." NOTE: the limit is per PROCESS and appears in the WWDC transcript, NOT on the current `init(named:)` doc page (I fetched it — no limit sentence).**
  - Sources: [WWDC22 "What's new in Screen Time API"](https://developer.apple.com/videos/play/wwdc2022/110336/) (exact transcript quote above); [init(named:) doc](https://developer.apple.com/documentation/managedsettings/managedsettingsstore/init(named:)) (limit absent); corroborated by [yosshi4486 Medium "Limitations of Screen Time-Related APIs"](https://medium.com/@yosshi4486/limitations-of-screen-time-related-apis-3ebf7c371962).
  - Confidence: Apple official (WWDC transcript). The "not in the API reference" part is directly falsifiable if Apple later adds it.

- **Claim: There is an UNDOCUMENTED ~50-token limit per shield setting: assigning >50 tokens to `store.shield.applications` or `store.shield.webDomains` causes the store to shield NOTHING and the property reads back nil. Confirmed by a second developer on iOS 17.2: "50 or less works perfectly, 51+ tokens doesn't block any apps." No Apple response in-thread. (Separately, kingstinct docs: "Apple currently limits domains and exceptDomains to 50 entries each" for web content filter policies.)**
  - Sources: [forum thread 733361](https://forums.developer.apple.com/forums/thread/733361); [kingstinct README](https://github.com/kingstinct/react-native-device-activity).
  - Confidence: Multiple forum reports, NOT in Apple docs — unofficial, version-dependent (verified through iOS 17.2 in-thread; re-test on current iOS). Combined implication often cited: 50 stores × 50 app tokens ≈ 2,500 shieldable apps max.

- **Claim: `clearAllSettings()` ("Clears all settings for this store") exists on every store; iOS 16 added type-level `ManagedSettingsStore.stores` (names of all configured stores) — WWDC22: "you can now remove all the settings in any given named store all at once."**
  - Sources: [ManagedSettingsStore doc](https://developer.apple.com/documentation/managedsettings/managedsettingsstore); [WWDC22](https://developer.apple.com/videos/play/wwdc2022/110336/).
  - Confidence: Apple official.

- **Claim: Applied settings are enforced by the SYSTEM, not by your running app: they persist across app termination and device reboots until your app sets them to nil / calls `clearAllSettings()` (this is why DeviceActivity monitor extensions can toggle restrictions while the app is dead). Persistence-until-cleared is implied by the doc sentence "Changing the value of a setting to nil deletes your app's configuration for that setting from the device," but Apple has NO explicit "survives reboot" sentence.**
  - Sources: [ManagedSettingsStore doc](https://developer.apple.com/documentation/managedsettings/managedsettingsstore); [WWDC21](https://developer.apple.com/videos/play/wwdc2021/10123/) (DeviceActivity extension model); community guides ([pedroesli](http://pedroesli.com/2023-11-13-screen-time-api/), [Julius Brussee Medium guide](https://medium.com/@juliusbrussee/a-developers-guide-to-apple-s-screen-time-apis-familycontrols-managedsettings-deviceactivity-e660147367d7)).
  - Confidence: Apple official (implication) + strong community consensus; explicit reboot statement not found — flagged.

- **Claim: If the user deletes your app, its managed settings/shields are removed by the system (restrictions don't orphan). Additionally, on individually-authorized devices users can neuter your app anytime via Settings → Screen Time (revoking Screen Time access), which developers report as an easy bypass (forum thread "Screen time API can be disabled easily", 727291). On CHILD devices, WWDC21: "Once your app has been approved by the guardian, it cannot be removed from the device without guardian approval."**
  - Sources: [WWDC21](https://developer.apple.com/videos/play/wwdc2021/10123/) (child-device quote); [thread 727291](https://developer.apple.com/forums/thread/727291); cleanup-on-uninstall is community consensus (e.g., one-sec/Opal support docs, blog guides).
  - Confidence: WWDC quote is Apple official. Settings-removed-on-uninstall: widely reported/expected but I found NO explicit Apple doc sentence — flag as high-confidence community consensus, unverified against official docs.

## 5. Other ManagedSettings capabilities (brief)

- **Claim: `application.denyAppRemoval: Bool?` — "A Boolean value that indicates whether to prevent the user from removing applications" (device-wide: blocks deleting ANY app, not just yours); `application.denyAppInstallation`; `application.blockedApplications: Set<Application>?` ("A set of applications for the system to block" — hides/blocks rather than shields; community notes it works with `Application(bundleIdentifier:)` for known bundle IDs, unlike token-based shields). All iOS 15+.**
  - Sources: [ApplicationSettings doc](https://developer.apple.com/documentation/managedsettings/applicationsettings); [adriatiks.blog "Preventing app removal on iOS"](https://adriatiks.blog/2024/09/29/preventing-app-removal-on-ios/); [thread 729717](https://developer.apple.com/forums/thread/729717) (denyAppRemoval only honored when FamilyControls-authorized).
  - Confidence: Apple official (properties) + blogs/forums (behavioral nuances).
- **Claim: Other groups: `dateAndTime.requireAutomaticDateAndTime`, `media` (max movie/TV ratings, explicit content), `webContent.blockedByFilter: WebContentSettings.FilterPolicy?` ("The current policy for filtering websites" — policies incl. auto/all/specific with exception domain sets), `passcode.lockPasscode`, `cellular`, `gameCenter`, `siri`, `appStore` (rating limits, require password), `safari` (deny/cookie policy), `account.lockAccounts`.**
  - Sources: [ManagedSettingsStore doc property list](https://developer.apple.com/documentation/managedsettings/managedsettingsstore); [WebContentSettings doc](https://developer.apple.com/documentation/managedsettings/webcontentsettings).
  - Confidence: Apple official (names/abstracts); I did not verify each behavior individually.

## 6. `.all(except:)` and the "new apps" gotcha

- **Claim: `store.shield.applicationCategories = .all(except: tokens)` shields "all apps and websites, except content that you specify" — the standard way to build an allowlist ("block everything except X"). Because the policy is category/device-wide rather than a token snapshot, apps installed AFTER the policy is set are shielded too (same for `.specific(categories)`: a newly installed app belonging to a shielded category gets shielded automatically). By contrast, `includeEntireCategory: true` on the picker snapshots individual app tokens at selection time, so `applicationTokens`-based shielding does NOT pick up later installs — a frequently-cited integration gotcha.**
  - Sources: [ActivityCategoryPolicy doc](https://developer.apple.com/documentation/managedsettings/shieldsettings/activitycategorypolicy) (policy semantics); [FamilyActivitySelection.includeEntireCategory doc]( https://developer.apple.com/documentation/familycontrols/familyactivityselection); forum discussions [721973](https://developer.apple.com/forums/thread/721973), [710346](https://developer.apple.com/forums/thread/710346), [kingstinct README](https://github.com/kingstinct/react-native-device-activity).
  - Confidence: Policy wording is Apple official; the dynamic-vs-snapshot behavior for NEW installs is community consensus/inference, not an explicit doc sentence — flagged.
- **Claim: `.all()` known holes: it shields most but not all apps — reported exclusions include Phone, Messages (varies by version), Settings, Clock, Find My, Maps, Health; and anything in the user's Screen Time "Always Allowed" list is never shielded by category policies. Some third-party apps report that with "block all," per-app exceptions are ignored (one-sec: "When selecting Block all… the exempted list is ignored" — recommending the iOS Always Allowed list as workaround).**
  - Sources: [thread 729891 "ManagedSettings can't shield Messages"](https://developer.apple.com/forums/thread/729891); [thread 718251](https://developer.apple.com/forums/thread/718251); [one-sec help article](https://tutorials.one-sec.app/en/articles/3036354).
  - Confidence: Multiple forum reports + vendor docs; version-dependent (exact system-app exclusion list has shifted across iOS releases) — unofficial.

## Cross-cutting caveats

- Version-dependence: token-rotation bug (iOS 17.5→26 beta reports), picker OOM crash (iOS 16→18 reports), 50-token shield limit (verified iOS 17.2) are all bug-class behaviors that may change in any release; the WWDC22 50-store limit and extension-only name access are stated design.
- Access to any of this requires the Family Controls entitlement (`com.apple.developer.family-controls`); the distribution entitlement must be requested from Apple, and `AuthorizationCenter.requestAuthorization(for: .individual)` (iOS 16+) or child/guardian flow must succeed — not covered in depth here but a precondition for every claim above.
- riedel.wtf and the Medium limitations article were 403-blocked from direct fetch; their claims are cited via search-indexed excerpts — quotes from those two should be re-verified before publication.
